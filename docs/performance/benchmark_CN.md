# 基准测试与容量验收

正确性、组件开销与部署容量回答不同的问题。

| 验证 | 范围 |
| --- | --- |
| C++ 回归测试 | 消息正确性、重连、关闭与回调行为 |
| 本地组件基准 | 收包缓冲申请、拆包与私有数据库调用开销 |
| 跨机器负载与长时间运行 | 目标负载下的吞吐量、延迟、CPU、内存与故障恢复 |

部署目标按多进程下 10–20 万同时连接预设，不表示单进程已达到该容量。测量前需要确定活跃消息频率、包体大小、进程数量、连接分布和故障条件。

正确性检查见[网络回归测试](../networking_CN.md)，传输层测量见 [arknet 性能报告](https://openarkstudio.github.io/arknet/zh/performance/)。TODO：发布完整的跨机器部署验收报告。

## 应用收包缓冲测量

[收包缓冲报告](receive-buffers_CN.md)记录已完成的本地组件测量、机器配置、中位数与范围，并保留吞吐量下降的组合。它使用可编译的 C++ 基准，对比 4、64、512 KiB 初始容量。这些组件数据补充上面的部署矩阵，不能代替跨机器负载验收。

## 数据库回调与协程测量

[数据库报告](database-coroutines_CN.md)对照 ark 私有数据库服务、手动执行器和任务组中的回调与 Asio 协程：56 组配置、336 个独立进程，覆盖两种包体、连接数、在途请求数，以及连续或 1 ms 更新间隔。SVG 图表默认展示吞吐与 CPU，响应时间、进程内存和完整表格可展开查看。这些本机短时数据不代表部署容量。
